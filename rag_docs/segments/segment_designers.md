# Сегмент: Проектировщики и инжиниринговые компании

## 📋 Профиль сегмента

| Параметр | Значение |
|----------|----------|
| Кто это | Проектные бюро, инжиниринговые компании, НИИ, отделы главного инженера на предприятиях |
| Типичный размер | 10–200 человек, оборот 50–500 млн ₽/год |
| ЛПР | ГИП (главный инженер проекта), ведущий проектировщик ОВ/ОВК, технический директор, руководитель отдела |
| Процесс закупки | ТЗ → расчёт → подбор оборудования → спецификация → согласование с заказчиком → тендер/закупка |
| Цикл сделки | 2–8 недель на этапе проектирования + 1–3 месяца на согласование закупки |
| Ключевой драйвер | Прохождение госэкспертизы, соответствие СП/ГОСТ, точность расчётов, наличие документации |

## 🎯 Боли и потребности (специфичные для сегмента)

### Технические боли
| Боль | Проявление | Почему важно для проектировщиков |
|------|-----------|---------------------------------|
| Нет точных характеристик оборудования | В каталоге указаны только диапазоны, нет аэродинамических кривых | Невозможно выполнить точный расчёт, риск ошибки в проекте |
| Отсутствие BIM-моделей или 3D-габаритов | Нет файлов для интеграции в проект | Приходится моделировать вручную = время = риск несовпадения |
| Оборудование не проходит экспертизу | Нет сертификатов ГОСТ/ТР ТС, пожарных протоколов | Задержка согласования проекта, риск переработки раздела |
| Несоответствие заявленных и реальных параметров | В проекте заложен один расход/давление, по факту — другое | Переделка проекта или замена оборудования на этапе монтажа |

### Процессуальные боли
| Боль | Проявление | Почему важно |
|------|-----------|-------------|
| Поставщик не даёт расчёты | Приходится делать аэродинамический/тепловой расчёт самостоятельно | Нагрузка на проектировщика, риск ошибки, задержка выпуска проекта |
| Долгое согласование ТЗ с поставщиком | Ответ на технический запрос идёт 3–5 дней | Сдвигает график выпуска рабочей документации |
| Нет оперативной техподдержки | При возникновении вопроса на этапе проектирования нет быстрого ответа | Простой в работе, риск принятия неоптимального решения |

### Коммерческие и административные боли
| Боль | Проявление | Почему важно |
|------|-----------|-------------|
| Отсутствие референсов по аналогичным объектам | Невозможно обосновать выбор оборудования заказчику | Сложности с защитой проектных решений, риск замены на этапе закупки |
| Нет гибкости под нестандартные задачи | Оборудование только серийное, нет возможности адаптации | Приходится искать альтернативы или перепроектировать узел |
| Сложности с заменой позиции в спецификации | Если оборудование снято с производства или нет в наличии | Переработка раздела проекта, согласование с экспертизой и заказчиком |

## 💬 Язык коммуникации: что говорить / что не говорить

### ✅ Говорить (триггеры доверия)
| Фраза | Почему работает для проектировщиков |
|-------|-------------------------------------|
| «Предоставляем аэродинамические кривые и расчётные листы» | Закрывает потребность в точных данных для проекта |
| «BIM-модели в формате Revit/IFC + 2D-чертежи» | Интеграция в проект без ручной доработки |
| «Полный пакет сертификатов: ГОСТ, ТР ТС, пожарные протоколы» | Гарантия прохождения госэкспертизы |
| «Инженер-консультант на связи для подбора под ТЗ» | Быстрое решение технических вопросов без задержек |
| «Опыт прохождения экспертизы: 50+ согласованных проектов» | Снижение риска переработки раздела |
| «Возможность кастомизации под нестандартные параметры» | Гибкость при работе со сложными объектами |

### ❌ Не говорить (триггеры отторжения)
| Фраза | Почему отталкивает проектировщиков |
|-------|-----------------------------------|
| «Подберём на глаз, потом уточним» | Не соответствует требованиям точности проекта |
| «Документация будет позже» | Создаёт риски задержки выпуска РД |
| «Это серийная модель, других нет» | Не решает задачу нестандартных параметров |
| «Скидка 15% при заказе от 1 млн» | Не релевантно на этапе проектирования (решает закупка) |
| «Монтаж — ваша зона ответственности» | Не их боль, это на этапе реализации, а не проектирования |

## ❓ Специфичные квалификационные вопросы (не из общего банка)

> Эти вопросы уникальны для сегмента и не дублируют `sales_questions_bank.md`.

### Вопросы по проекту и экспертизе
1. «На какой стадии проект: П, Р, рабочая документация?»
2. «Какие нормативы применяются: СП, ГОСТ, международные стандарты?»
3. «Есть ли требования по классу энергоэффективности или шумовым характеристикам?»
4. «Кто проводит госэкспертизу: Главгосэкспертиза, региональная, внутренняя?»

### Вопросы по документации и интеграции
5. «В каком формате нужны модели: Revit, IFC, DWG, 3D PDF?»
6. «Требуется ли расчёт воздухообмена, аэродинамики, теплопотерь от поставщика?»
7. «Есть ли чек-лист документов для прохождения экспертизы по разделу ОВ?»
8. «Как проходит согласование замены позиции в спецификации?»

### Вопросы по процессу подбора
9. «Используете ли типовые решения или каждый объект требует индивидуального подбора?»
10. «Кто финально утверждает спецификацию: ГИП, заказчик, экспертиза?»
11. «Есть ли ограничения по бюджету оборудования на этапе проектирования?»
12. «Как быстро нужен ответ на технический запрос?»

## ⚠️ Типичные возражения проектировщиков + контекстная отработка

> Формат: возражение → ссылка на универсальную стратегию → специфичный акцент для сегмента.

### Возражение: «Нет точных аэродинамических характеристик»
- **Ссылка:** `sales_objections.md` #tech_data_provide
- **Контекст для проектировщиков:** Для них точность данных = возможность защитить проект перед экспертизой. Перефразируйте: «Понимаю, что для расчёта нужны точные кривые. Инженер подготовит аэродинамическую характеристику и расчётный лист под ваши параметры за 1 день. Это закроет вопрос для экспертизы и упростит защиту проекта. Отправить шаблон ТЗ для расчёта?»

### Возражение: «Нет BIM-моделей или 3D-габаритов»
- **Ссылка:** `sales_objections.md` #bim_support
- **Контекст:** Предложите не просто «модели есть», а конкретные форматы и интеграцию. «Предоставляем модели в форматах: Revit 2024 (с параметрами в свойствах), IFC для совместимости, DWG для 2D-чертежей. Это интегрируется в ваш проект без ручной доработки. Нужен конкретный формат под вашу платформу?»

### Возражение: «Оборудование может не пройти экспертизу»
- **Ссылка:** `sales_objections.md` #docs_cert
- **Контекст:** Акцент на «реестр документов под объект» и опыт согласования. «Вся продукция сертифицирована по ГОСТ и ТР ТС, пожарные протоколы в наличии. Готовы предоставить реестр документов именно под ваш объект: какие сертификаты, какие протоколы, какие номера. Плюс опыт: 50+ проектов прошли экспертизу с нашим оборудованием. Это закроет вопросы?»

### Возражение: «Нужен расчёт под нестандартные параметры»
- **Ссылка:** `sales_objections.md` #custom_calc
- **Контекст:** Предложите не «мы посчитаем», а «инженер закреплён за проектом». «Закрепляю инженера за вашим проектом: он сделает аэродинамический/тепловой расчёт под ваши параметры и подготовит обоснование для экспертизы. Это бесплатно и ускоряет выпуск РД. Когда удобно передать исходные данные?»

## 📄 Документация и процесс: что требуют проектировщики

### Обязательный пакет документов
| Документ | Зачем проектировщику | Формат предоставления |
|----------|---------------------|----------------------|
| Аэродинамические кривые и расчётные листы | Для точного расчёта сети и обоснования выбора | PDF + Excel с формулами, по запросу — исходные данные |
| Сертификаты ГОСТ/ТР ТС, пожарные протоколы | Для прохождения госэкспертизы | Электронно с ЭЦП + реестр номеров для проверки |
| Паспорта изделий с точными характеристиками | Для спецификации и рабочей документации | В каждом коробе + электронный архив с поиском по артикулу |
| BIM-модели и 2D-чертежи | Для интеграции в проект без ручной доработки | Revit 2024, IFC, DWG + инструкция по вставке |
| Обоснование выбора оборудования | Для защиты проектного решения перед заказчиком | Краткий отчёт: параметры, сравнение, выводы |

### Процесс взаимодействия (типичный)

Технический запрос от проектировщика → 2. Закрепление инженера-консультанта → 3. Подготовка расчётов, характеристик, документации → 4. Согласование спецификации → 5. Фиксация артикулов в проекте → 6. Передача в закупку/тендер → 7. Поддержка на этапе выпуска РД → 8. Комплект документов для экспертизы


### Критичные точки для ускорения
- Ответ на технический запрос: не более 24 часов
- Расчёты и характеристики: подготовка за 1 рабочий день
- Документация: готовность пакета «под экспертизу» до выпуска РД, а не после
- BIM-модели: проверка совместимости с версией ПО проектировщика
